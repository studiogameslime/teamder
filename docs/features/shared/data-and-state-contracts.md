# חוזי נתונים ומצבים משותפים

עודכן 7.10.2026 מול `8e8fde5`. המסמך מרכז כללי עבודה שחוזרים בכמה מסכים. יש לפתוח את מסמך הפיצ׳ר לפני שינוי.

## מסלול שינוי

מסך/רכיב → שירות → מסד או פונקציית שרת → ממיר קריאה → חנות נתונים → בורר מצב → מסך. דמו עשוי לעקוף את הממיר ואת ההרשאה; מעבר בדמו בלבד אינו מוכיח ששדה חדש נקרא אצל משתמש אמיתי.

מקורות: [`src/firebase/firestore.ts`](../../../src/firebase/firestore.ts), [`src/types/index.ts`](../../../src/types/index.ts), [`src/services`](../../../src/services), [`src/store`](../../../src/store), [`functions/src`](../../../functions/src).

## יחידות והגדרות

| מושג | משמעות | מה אסור להסיק |
|---|---|---|
| מחזור | ערב כדורגל שלם | מספר משחקים אינו מספר מחזורים |
| משחק | משחק אחד בתוך הערב | שערי פנדלים אינם שערי שדה |
| אורח התחברות | זהות אנונימית לצפייה | אינו בהכרח אורח ידני בסגל |
| אורח סגל | שחקן ידני ללא זהות משתמש מלאה | אינו יכול לשמש תמיד כל משתמש רשום |
| בקשה | פעולה ממתינה לאישור | אינו מקום מאושר בסגל |
| המתנה | רשימה נפרדת מההרכב הפעיל | אינו משתתף פעיל לחלוקה |
| עונה חתומה | תמונת נתונים בטווח סגור | אין להחליף בנתוני העונה הפעילה |
| נתון חסר | מידע שלא קיים או לא הובא | אינו אפס ולא רשימה ריקה אמיתית |

מודול [`eveningPlayed.ts`](../../../src/utils/eveningPlayed.ts) קובע אם ערב התקיים. שינוי בו נבדק גם מול גרסת השרת ומבחני התאמה. סיום עונה אינו איפוס מוני החיים האישיים. פירוט תחומים ומכנים נמצא במסמכי הסטטיסטיקה.

## זהות וכשל

[`staleSession.ts`](../../../src/services/staleSession.ts) מגדיר שגיאה מובחנת. תגובה מסשן ישן אינה יכולה לחזור כרשימה ריקה ולדרוס את מועדוני המשתמש ובחירתו. כשל רשימה אחרת דורש בדיקת הצרכן לפני ״תיקון״ גורף; אין להחיל התנהגות חדשה בלי להבין מה נשמר ומה מרונדר.

יש לשאת מזהי מסמכים מהתוצאה המקורית ולא להקלידם מהדפסה. שינוי הרשאות, פריסה או מיגרציה אינם חלק מהמיפוי. כללי הגישה הקיימים נקראו לצורך הבנת חוזים ולא שונו.

## ניווט

[`src/navigation`](../../../src/navigation) מכיל את שערי הכניסה, הלשוניות והמחסניות. אותו מסך יכול לשאת כמה שמות מסלול; שם קובץ אינו תמיד שם מוצר. `ProfileScreen` הוא בית המשתמש. מסך משותף חייב להירשם בכל מחסנית שבה יש כניסה אליו. המרת טיפוס עיוורת של navigate יכולה להסתיר יעד חסר.

כלי הבדיקה מוסיף פתיחה ישירה בסביבת פיתוח בלבד. נתוני פתיחה מיושנים, מזהה חסר או פרמטר שגוי אינם ראיה למסלול המוצר. יש לאמת גם דרך הכניסה הרגילה לפני קביעת תקלה בניווט.

## כיווניות וראיות

הילד הראשון בשורה נמצא מימין תחת forceRTL. `RTL_LABEL_ALIGN='left'` הוא חוזה הפרויקט; אין לשלב אותו עם writingDirection='rtl' או להוסיף row-reverse. יש לבודד טקסט חלש/לטיני ולבדוק צילום, לא רק לקרוא את הסגנון.

הערות מקור ישנות עשויות לסתור את המימוש, למשל מגבלות סגל היסטוריות או תמיכה בתמונות. הכריעו לפי ענף הקוד המופעל, הטיפוס, השירות והממיר יחד. אין להפוך הערה ישנה להבטחת מוצר.
