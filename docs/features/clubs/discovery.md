## טעינת רשימת המועדונים, 3.11.2026

מסלול הכניסה נשאר לשונית מועדונים, `CommunitiesFeed`, במסך `src/screens/communities/PublicGroupsFeedScreen.tsx`. הוחלף כדור הטעינה הראשונית ב-`src/components/loading/ClubFeedSkeleton.tsx`. הכותרת, שער ההתחברות ושורת החיפוש והמסננים נשארים באותו עץ תצוגה בזמן ההמתנה. אין זמן המתנה מלאכותי ואין שינוי בשירות, בהרשאות, בניווט, בסינון או במכנים.

| מצב | תנאי | תצוגה |
|---|---|---|
| טרם התקבלה תשובה | `items === null && !loadFailed` | שלושה כרטיסי שלד ושני אזורי כותרת, כולל הפריים שלפני הפעלת הטעינה |
| התקבלה רשימה | `items !== null` | התוכן הקיים, לרבות רשימה ריקה שאושרה בקריאה מוצלחת |
| רענון או חיפוש | יש תשובה קודמת ובקשה חדשה | הכרטיסים הקודמים נשארים מוצגים, עם חיווי הרענון הקיים |
| כשל ראשון | `items === null && loadFailed` | הודעת כשל וכפתור נסו שוב, ללא מצב ריק מומצא |
| כשל ברענון או בחיפוש | יש תשובה קודמת וכשל | הנתונים הקודמים נשמרים עם הודעת כשל ואפשרות לנסות שוב |

אפקט הקריאה ממשיך להשתמש ב-`listPublicGroups` או `searchPublicGroups`, עם השהיה של אפס לחיפוש ריק ו-250 אלפיות שנייה לחיפוש מוקלד. `loadFailed` מתאפס בתחילת בקשה; בכשל לא משנים את `items`. ניסיון חוזר מגדיל את `refreshTick`. ביטול האפקט פוסל תשובות מאוחרות, כולל כשל, ואינו כותב למסד.

השלד משתמש ב-`SkeletonRegion` המשותף, עם פעימה אחת, תמיכה בצמצום תנועה, הודעת טעינה נגישה אחת והסתרת בלוקים דקורטיביים מקורא מסך. גוף הכרטיס מופיע ראשון בשורה ולכן מימין בכיווניות האפליקציה. אזור התמונה משמאל ברוחב 41.5 אחוז ובגובה הכרטיס; הכרטיסים הם מצייני מקום ואינם קביעה שיש שלושה מועדונים.
