## פירוט מימוש ונקודות שינוי — העמקה 07.10.2026

## אימות ותיקונים מקומיים — 9.10.2026

ממצאי הסקירה החוזרת מ־8.10 תוקנו מקומית, והסבב המורחב תיקן מקרי החלפת הזמנה, זהות ובחירה. `App.tsx` שומר את הקישור; `RootNavigator` הוא צרכן הניווט היחיד. פתיחת הזמנה אינה מבצעת הצטרפות. בחירה שאינה ההזמנה מדכאת את פתיחתה האוטומטית בלי למחוק את המזמין או מקור הרכישה.

לפני ניווט, גם בענף האישי וגם בענף מחזור/מועדון, נבדקים מחדש `pendingActionMatches` ו־`canNavigateInvitation`: אותו מזהה משתמש ואותו מצב אורח, פרופיל והיכרות לחשבון מלא, שער `app`, מועדונים טעונים ואי־דיכוי בחירה. פירוק הרכיב מונע ניווט וסימון מאוחרים; שינוי זהות או פעולה מתזמן צרכן חדש במקום לתת לתשובה ישנה למשוך את המשתמש.

ניווט שמחזיר כישלון מקבל עד שלושה ניסיונות חוזרים, אחרי 500, 1,000 ו־1,500 מילישניות. `invitePreflight` מוגבל ל־4,000 מילישניות; בפקיעה נפתח היעד בצורה אופטימית כדי שמסך היעד יטפל בטעינה או בגישה. תשובת מחיקה מאוחרת אינה מוחקת הזמנה חדשה. כרטיס אישי ללא מזמין אינו מוצג; הסימון `inviteLanding` נכתב רק לאחר ניווט מוצלח.

גובה שורת כרטיס הכניסה מוגדר כעת `minHeight:CARD_HEIGHT` במקום גובה קשיח. זהו אימות בקוד בלבד; לא רינדור מקורי בגופן מוגדל. בכרטיס הכניסה נוספו בידוד שם מעורב, תג מוגבל רוחב ותווית נגישות הכוללת את הכותרת, המזמין וההסבר. בשורת החשבון הקיים הוסר השילוב האסור של כיווניות ויישור. צילום הכניסה המקורי בגופן מערכת מוגדל עדיין נדרש; צילומי דפדפן אינם מוכיחים את המסך המקורי.

### השלמת שחזור אחרי ספק — 10.10.2026

`refreshFromSession(expectedUid)` דורש פרופיל מלא עם מזהה תואם לספק. כשל, תוצאה ריקה, אורח או מזהה אחר מאפסים את פרופיל החנות, מגדירים `profileRestoreFailed` וזורקים לקורא. הזהות בספק אינה מוחלפת. `useAuthenticatedAction` תופס את הכשל וחוזר לפני `resumePendingAction`; מסך הכוונה מפנה לשער השחזור. `hydrate` של הניסיון החוזר קורא את הזהות שכבר התחברה וממשיך בשערים הרגילים. נבדקו גם הימנעות מהמשך הפעולה וגם מעבר מכשל לפרופיל תואם. אין התחברות ספק חיה בבדיקה.
