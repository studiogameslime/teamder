# שחקני המחזור, אורחים ותפריט שחקן

עודכן: 7.10.2026. מקור הקוד: `8e8fde5`, גרסה `1.1.35`. מסמך זה מתאר את הקוד; מצב חנות ופריסת שרת דורשים ראיה נפרדת.

## כניסה ותפקידים

MatchDetails → שחקנים; או MatchPlayers {gameId}

משתמש רואה זהות; דירוג פנימי ותפריטי ניהול למנהל בלבד. אורח ידני אינו פותח כרטיס משתמש שאינו קיים.

## רכיבים ומצבים

| רכיב / מצב | התנהגות וחוזה |
|---|---|
| רשומים | אווטאר, שם, זמן הצטרפות, מנהל, דירוג פנימי לפי סמכות; מונה כולל אורחים פעילים |
| המתנה | מספור, אורחים waitlisted, הצעת מקום ואישור/ויתור |
| ממתינים לאישור | approveGameJoin / rejectGameJoin; בקשה לא נחשבת לשחקן רשום |
| ביטולים | רשימה עצמאית עם זמן; כיווניות בזמן יחסי ובשמות לטיניים |
| ניהול סדר | adminReorderRoster מחליף סדר הרשומים וההמתנה, עם מניעת לחיצה כפולה |
| תפריט שחקן | פעולות משתנות לפי סמכות וזהות: הסרה ודירוג; removePlayer דורש אישור |
| אורח | GuestModal להוספה/עריכה; שם ודירוג משוער; אורח בהמתנה אינו משתתף בחלוקה |

## מסלול נתונים ומקומות שינוי

[`src/screens/games/MatchPlayersScreen.tsx`](../../../src/screens/games/MatchPlayersScreen.tsx); [`src/components/match/tabs/MatchPlayersTab.tsx`](../../../src/components/match/tabs/MatchPlayersTab.tsx); [`src/components/GuestModal.tsx`](../../../src/components/GuestModal.tsx)

## בדיקות וראיות

guestPromotion, draftTeamsView, הרשמה וכיווניות. לראות דירוג כמנהל וכחבר; אין להסיר משתמש אמיתי לצורך צילום.

צילומי המיפוי מהאמולטור נעשו במצב נתוני דמו, המסומן בפס כתום. הם מוכיחים את הרכיב והמצב המוצגים בלבד, ולא ממירי Firebase, נתוני ייצור או כתיבה. צילומי תיקונים קודמים מסומנים בנפרד. שגיאת מזהה, מצב טעינה או שער הגנה אינם הוכחת הפעולה המלאה.

## גבולות והערות תחזוקה

התפריט משתמש ברכיבי התפריט המשותפים; מסמך זה מפרט את הקשר הפעולות. מצב צילום נוכחי אינו מוכיח את כל התפקידים.

לפני שינוי פתח את הקוד המקושר ואת [כללי הפרויקט](../../../AGENTS.md). לאחר שינוי עדכן במסמך זה את התאריך, נקודת הקוד, המצבים שהתעדכנו, הבדיקות והצילום. אין לטעון שכל מצב/תפקיד נבדק רק משום שקיים צילום אחד.
