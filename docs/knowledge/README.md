# ידע עבודה — Teamder

מפת הפיצ׳רים המעודכנת מול `8e8fde5`, גרסה `1.1.35`, נמצאת ב־[תיעוד המסכים והפיצ׳רים](../features/README.md). שם נשמרים המצבים, הצילומים, הממצאים וכללי התחזוקה. מצב ההפצה מתועד בנפרד ביומן הגרסה.

המפתח שלהלן נכתב ב־7.10.2026 מול `28db7b2`, גרסה `1.1.32`, ונשמר כהקשר היסטורי. זהו מפתח לעבודה, לא אישור תקינות או תיאור של מצב הייצור בזמן אמת; במקרה של סתירה יש לבדוק את הקוד הנוכחי ומפת הפיצ׳רים.

לפני שינוי קרא את [כללי הפרויקט](../../AGENTS.md). לאחר מכן השתמש במפה להלן כדי לפתוח רק את הקוד והמקורות הרלוונטיים. הקוד הנוכחי קובע מה ממומש; מסמכים היסטוריים מסבירים החלטות, תקלות וכוונה. כשיש סתירה יש לבדוק את ההקשר והתאריך, ולא להעתיק פתרון ישן.

## מה המוצר עושה

מארגן ערבי כדורגל של מועדונים: הרשמה, זמינות, חלוקת קבוצות, משחקים בתוך ערב, תוצאות, סטטיסטיקות, עונות וצ'אטים. מחזור הוא ערב שלם; משחק הוא אחד המשחקים בתוכו. אין להציג למשתמש את המילה ״משחקון״. אורח של התחברות אנונימית ואורח ששובץ ידנית לערב הם שני מושגים שונים.

היישום מבוסס על Expo 53, React Native 0.79.6, React 19 ו־TypeScript, עם Zustand, Firebase ושירותי שרת. קיימים רכיבים מקוריים וערכת Joryio מקומית; אין להניח ש־Expo Go מספיק להרצה. גרסת `package.json` אינה גרסת החנות.

## חוזים שאסור לשבור

- סדר הכרעת מצב הבית הוא חי, המתנה, אישור ממתין, היום למשתתף, רשום, נפתח בקרוב, סגור, מלא, פתוח. הסדר מאומת בקוד `homeRoundState.ts`.
- `StaleSessionError` קיים בקוד ומזוהה גם לפי שם. אין להחזיר `[]` במקום כשל של זהות ישנה: הדבר עלול למחוק מועדונים ובחירה מקומית. בדוק גם את הצרכן בחנות הנתונים.
- `eveningPlayed.ts` הוא המקור לשאלה אם ערב התקיים. קיימת גרסת שרת ומבחן התאמה; אין ליצור תנאי חדש בכל מסך.
- סטטיסטיקות מועדון פעילות, תמונת עונה חתומה והיסטוריה אישית אינם אותו מאגר. סגירת עונה אינה איפוס של היסטוריה אישית. תמיד לזהות יחידה, תחום ומכנה לפני שינוי מספר.
- שדות חסרים, ערכים אפסיים ונתונים שנאספו רק מחלק מהערבים שונים זה מזה. אין להסיק זמן משחק מחלוקת קבוצות בסוף הערב בלבד.
- בממשק עברי עם `forceRTL`, הילד הראשון בשורה מופיע מימין. `RTL_LABEL_ALIGN='left'` משמש להתאמה במערכת זו. לא להוסיף `row-reverse` או שילובי כיווניות עיוורים; בידוד דו־כיווני לטקסט לטיני לפי הכללים.
- כללי הרשאות, פריסה, בנייה לחנויות ונתוני ייצור כפופים ל־`AGENTS.md`. אין לבצע אותם כחלק אוטומטי מתיקון. אין ליצור חשבונות או מועדוני בדיקה; סביבת בדיקה עלולה להשתמש בחשבון אמיתי.

## דרך עבודה על תקלה או פיתוח

1. זהה מסך, פלטפורמה, גרסה, משתמש/תפקיד, מועדון ועונה. לבאג: רשום שחזור, ציפייה ותוצאה בפועל; בקש רק מידע שחסר לשחזור.
2. פתח את הקוד מהטבלה ואת המקור ההיסטורי המתאים מתוך [קטלוג המקורות](sources.md). לחזות הממשק פתח את עמוד המקור, לא רק את הסיכום.
3. עקוב מהכתיבה דרך ממיר הנתונים, השירות, חנות הנתונים ובורר המצב עד למסך. קבע אם זו תקלת נתון, הרשאה, זהות, חישוב או תצוגה.
4. לפני שינוי חפש מבחן קיים עבור החוזה. אחרי שינוי קוד הרץ `npm run typecheck` ו־`npm test -- --runInBand`, בהתאם לכללי הפרויקט. שינוי בממשק דורש צילום ותצוגה בפועל, כולל מצבים קיצוניים רלוונטיים.
5. שינוי בעונות או במימוש משוכפל מחייב את מבחני ההתאמה. בדיקות כללים דורשות Java 21 ומעלה, הרצה סדרתית וכל הקובץ; הפקודה הקיימת היא `npm run test:rules`. אין לשנות כללים בלי בקשה מפורשת.
6. סכם מה תוקן, כיצד נבדק ומה נותר לא מוכח. דיווחי פולס והיומן מטופלים לפי `AGENTS.md`. אין לסמן דיווח פתור רק כי השערה נשמעת סבירה.

מבחנים שימושיים: `tests/logic/groupHydrate.test.ts`, `homeRoundState.test.ts`, `homeAvailabilityView.test.ts`, `pairOrientation.test.ts`, `pendingActionMachine.test.ts`, `eveningPlayedMirror.test.ts`, `seasonAwardsMirror.test.ts`; וכן `tests/hooksAfterEarlyReturn.test.ts`, `tests/logic/analyticsWiring.test.ts`, `copyDirectionality.test.ts`.

להרצה מנותקת קיים במדריך הפרויקט `EXPO_PUBLIC_FOOTY_FORCE_MOCK=1`; החלפת משתני סביבה דורשת הפעלה מחדש. יש לבדוק את מסלול השירות הנבחר ואת חיבורי Firebase לפני כל כתיבה. הסיכום הזה אינו מאשר שהאמולטור או הסימולטור מותקנים ועובדים.

## גבולות הלמידה והשימוש בעתיד

נוצר אינדקס טקסט של כל 137 המסמכים ושל אינדקס התיעוד. נבדקו מבנה, כותרות וסיכומים, ונקראו לעומק מקורות נבחרים בנושאי תקלות אחרונות, בית, כניסה, עונות ועיצוב. נסקרו חזותית 144 עמודים המכילים תמונות באמצעות גיליונות מגע. זו סקירה רוחבית; אין כאן טענה לקריאה מלאה של כל שורה או פענוח כל צילום זעיר באודיטים הגדולים. מסמכים מאוחדים חוזרים על מסמכי המקור.

הקבצים כאן מאפשרים לשיחה חדשה להתחיל מהמפה בלי ללמוד מחדש את כל הארכיון. הם אינם זיכרון מובטח של המודל: יש לקרוא את המדריך בתחילת משימה ולפתוח קוד ומקור ממוקדים כשנדרש דיוק. עדכן את הידע אחרי שינוי משמעותי, עם תאריך והוכחה, ולא כתחליף לתיעוד בקוד.
