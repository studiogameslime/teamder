# תכנית בדיקות מלאה — אפליקציית Teamder

מסמך זה מגדיר תרחישי בדיקה לכל אזור. לכל בדיקה: מטרה · תנאים · משתמש · צעדים · תוצאה צפויה · מה לאמת (חזותי / אצל המשתמש השני / אחרי פתיחה-מחדש). מומלץ להריץ עם **שני משתמשים** בשני אמולטורים (מפורט בסוף).

**מקרא מצב:** לא-בוצע / עבר / נכשל / חסום. *הערה: בסבב הנוכחי הבדיקות בוצעו ברמת קוד; העמודה "תוצאה בפועל" תמולא בהרצה התנהגותית על מכשיר.*

לכל פיצ'ר יש להריץ, מעבר לתרחיש הרגיל, גם את **מטריצת-הקצה**: ללא נתונים · נתונים חלקיים · ערכי קצה · קלט שגוי · לחיצה מהירה/כפולה · חזרה-אחורה באמצע · סגירת אפליקציה באמצע · פתיחה-מחדש · רקע↔חזרה · אינטרנט חלש/מנותק/חוזר · פעולה מקבילה משני משתמשים · שינוי-נתון בזמן שהמסך פתוח · הרשאה חסרה · פעולה לא-מורשית · נתונים ישנים/כפולים · מעבר יום/שבוע · פעולה שכבר בוצעה.

## אזור א' — אימות, פרופיל, חברים, דירוגים
- ב-01 הרשמה בדוא"ל חדש → צפוי: חשבון+אונבורדינג. אמת: פתיחה-מחדש שומרת התחברות.
- ב-02 כתובת שכבר רשומה דרך Google/Apple → צפוי: הודעה "התחבר עם Google/Apple".
- ב-03 יציאה וכניסה כמשתמש אחר → אמת: אין דליפת נתונים/התראות מהחשבון הקודם.
- ב-04 כניסת אורח → צפוי: גישה מוגבלת, ללא פרופיל מלא.
- ב-05 עריכת שם/עמדה → אמת: נשמר, מתעדכן בכל המסכים, שורד פתיחה-מחדש.
- ב-06 החלפת אווטאר ואז **ביטול** → צפוי: התמונה המקורית נשמרת (בדיקת ת-14).
- ב-07 העלאת תמונה בכשל רשת → צפוי: הודעת שגיאה, ללא מצב שבור.
- ב-08 בקשת חברות: ב'→א', ואז א' פותח כרטיס של ב' → צפוי: "אשר בקשה" (בדיקת ת-03). אמת: אצל שני הצדדים.
- ב-09 אישור בקשה → אמת: חברות דו-צדדית, שני הצדדים רואים, שורד רענון (בדיקת ת-29).
- ב-10 שני אנשים מאשרים בקשות מאותו משתמש בתוך 24ש' → אמת: שני פושים (בדיקת ת-04).
- ב-11 הסרת חבר → אמת: מוסר משני הצדדים.
- ב-12 חסימה → אמת: הודעות החסום מוסתרות; בדוק אם הוא עדיין יכול לשלוח DM/פוש (בדיקת ת-25).
- ב-13 דירוג פנימי: מנהל מדרג → אמת: חבר רגיל אינו רואה בממשק; בדוק אם הנתון חשוף בקריאה (ת-13).
- ב-14 מחיקת חשבון → אמת: העברת/פירוק מועדונים, הסרה מרוסטרים, אנונימיזציה בצ'אט.

## אזור ב' — קהילות, חברות, הרשאות
- ק-01 יצירת מועדון (פתוח/סגור) → אמת: נשמר עם מיקום ותמונת-שער; מופיע ב"לידי" (בדיקת ת-19).
- ק-02 חיפוש מועדונים → אמת: תוצאות תקינות; שים לב לעלות-קריאה (ת-20).
- ק-03 הצטרפות למועדון פתוח → אמת: ניווט יחיד לדף המועדון (ת-B3); הופעה ברוסטר.
- ק-04 בקשה למועדון סגור → אישור/דחייה → אמת: פוש, audit "אושר ע"י", עדכון מונה-חברים.
- ק-05 דחיית בקשה בכשל רשת → צפוי: חיווי שגיאה (בדיקת ת-06).
- ק-06 שני מנהלים מאשרים אותה בקשה במקביל → אמת: אין כפילות, קיבולת נשמרת.
- ק-07 הזמנת חבר למועדון סגור → אמת: לא מופיע כ"בקשה" מזויפת (ת-28).
- ק-08 אדמין-עמית מנסה להסיר אדמין אחר → צפוי: הפעולה מוסתרת (בדיקת ת-07).
- ק-09 קידום/הורדת מנהל (יוצר בלבד) · מחיקת מועדון (יוצר בלבד) → אמת: הרשאות.
- ק-10 עזיבת מועדון על ידי היוצר → אמת: העברת-בעלות תקינה.
- ק-11 ניהול ציוד/כרטיסים → אמת: כרטיס-אדום פעיל חוסם הרשמה.

## אזור ג' — מחזור חיי משחק
- מ-01 יצירת משחק (חד-פעמי/חוזר) → אמת: נשמר; נראות ברירת-מחדל נכונה.
- מ-02 הרשמה עד מילוי → צפוי: הרשומים ואז רשימת המתנה; מכסה מדויקת (ללא off-by-one).
- מ-03 **פתיחת הרשמה עמוסה**: עשרות טאפים בו-זמנית → אמת: יישוב הוגן לפי זמן-טאפ; אין הבטחת-מקום מטעה (ת-17).
- מ-04 ביטול → אמת: הבא בהמתנה מקודם/מקבל הצעה + פוש (שני הצדדים).
- מ-05 הצעת-מקום: אישור/ויתור/הפקעה אחרי 20ד' → אמת: המקום עובר הלאה; ממתין-יחיד לא נתקע (ת-27).
- מ-06 שני משתמשים על המקום האחרון → אמת: רק אחד נכנס, השני להמתנה.
- מ-07 הוספת אורח (הרשאה לפי זמן) → אמת: תופס קיבולת; מלא → אורח בהמתנה.
- מ-08 **הסרת אורח שתופס מקום** → אמת: הבא בהמתנה מקודם (בדיקת ת-10).
- מ-09 השלמת שחקנים: "שלח לכל הפנויים באזור" → אמת: הצעות לשחקנים מתאימים; אישור filler לא חורג מקיבולת (בדיקת ת-01).
- מ-10 עריכת פרט זעיר (הערה) → אמת: האם נשלח פוש "עודכן" מיותר (ת-16).
- מ-11 שינוי זמן/מקום → אמת: פוש לכל ההרכב, תוכן מעודכן.
- מ-12 הורדת מכסה מתחת למספר הרשומים → אמת: איזון/חסימה (ת-21).
- מ-13 **חוזר שבועי**: ביטול מופע יחיד → אמת: הסדרה ממשיכה בשבוע הבא (בדיקת ת-09 — קריטי).
- מ-14 פתיחה-מתוזמנת (הרשמה/פומבי) → אמת: תזמון מדויק, פוש למנויים בפתיחת-הרשמה.
- מ-15 ביטול/מחיקת משחק → אמת: פוש-ביטול לכל ההרכב.

## אזור ד' — משחק חי, טיימר, רוטציה (קריטי)
- ל-01 מעבר ללייב (2 מכשירים) → אמת: אותו מצב אצל שניהם.
- ל-02 התחלת/עצירת/המשך/איפוס טיימר → אמת: **סנכרון בין המכשירים**, אין קפיצה/סטייה; כשל מציג חיווי (ת-18).
- ל-03 רקע/נעילת-מסך/חזרה אחרי זמן → אמת: הזמן נכון (מבוסס שעון-שרת, לא ספירה מקומית).
- ל-04 טיימר: מעבר לזמן-נוסף → אמת: שעון ראשי קופא, מונה-נוסף אדום; אין זמן שלילי מוצג.
- ל-05 **המסך נשאר דלוק** כל עוד הטיימר רץ (בדיקת ת-11 — כרגע נכשל).
- ל-06 חלוקת קבוצות / דראפט → אמת: חלוקה תקינה; דראפט resume אחרי עזיבת שחקן (ת-D3).
- ל-07 רוטציית מנצחת-נשארת + תור → אמת: מנצחת נשארת, מפסידה לתחתית, הבאה נכנסת ומולאת.
- ל-08 החזרת/הוצאת שחקן → אמת: אין מילוי-יתר של קבוצה.
- ל-09 שער (מבקיע+בישול) / ביטול-שער → אמת: נספר פעם אחת אצל שני המכשירים.
- ל-10 סיום משחקון / מנצחת / תיקו → אמת: ניצחון+שערים נזקפים בדיוק פעם אחת (קומיט אטומי).
- ל-11 שני משתמשים משנים תוצאה בו-זמנית → אמת: אין שכתוב/כפילות.
- ל-12 סיום ערב → אמת: קומיט אחרון, הקפאה, מניעת שינוי לאחר סיום.
- ל-13 סנכרון לשעון: baseElapsedMs → אמת: אותו זמן בשעון ובטלפון.

## אזור ה' — סטטיסטיקות ועקביות
- ס-01 תרחיש ידוע: משחק עם מספר משחקונים/מנצחים/שערים ידועים → חשב ידנית והשווה בכל המסכים.
- ס-02 עקביות "משחקים" בין פרופיל לטבלת מועדון (בדיקת ת-15).
- ס-03 עקביות: משחקונים = ניצחונות + הפסדים (+ תיקו) בטבלת המועדון.
- ס-04 בישולים במשחק חי → אמת: לא אפס (באג-עבר; אמור להיות סגור).
- ס-05 אי-כפילות: כניסה-חוזרת למשחק שהסתיים לא סופרת שוב.
- ס-06 גולים רטרו: הוספה/הסרה → אמת: לא נוגע במשחקונים/מנצח.
- ס-07 שחקן שסומן "לא הגיע" → אמת: לא נספר בערבים; בדוק אם נזקפים לו משחקונים/ניצחונות (ת-E4).
- ס-08 תארים/הישגים/רצפים → אמת: ספים נכונים, שורדים רענון.

## אזור ו' — התראות וקישורים
- ה-01 בקשת/דחיית הרשאת התראות + חסום → אמת: התנהגות תקינה.
- ה-02 רישום מזהה-התקן + מעבר חשבון → אמת: אין דליפה לחשבון הבא.
- ה-03 לכל אירוע (הזמנה/תזכורת/שינוי/ביטול/קידום/פנויים): נשלח? פעם אחת? לנמען הנכון? כותרת+תוכן+שם-משחק+שעה נכונים? פתיחה מובילה למסך הנכון?
- ה-04 תזכורת שעה-לפני → אמת: מדויקת, פעם אחת.
- ה-05 כפתורי פעולה בהתראה (אני-בא/מאשר-מקום/ויתור): לחיצה בהפעלה-קרה → אמת: פעולה+אישור פעם אחת (באג-עבר; אמור להיות מכוסה).
- ה-06 שינוי פרטי משחק → אמת: תוכן ההתראה מעודכן.
- ה-07 שיוך הזמנה (קישור/לוח/referrer) → אמת: המזמין נרשם נכון.
*הערה: קבלת פוש אמיתית תלויה בסביבה; יש לתעד מה אומת מקצה-לקצה ומה לא.*

- צ-05 זמינות: סימון + כיבוי מיקום → אמת: כיבוי מבטל קבלת הצעות; פין-ברירת-מחדל לא נשמר בשקט (ת-G availability).
- צ-06 "פנויים לשחק לידך" → אמת: ספירות בלבד (ללא זהויות), לפי רדיוס.

- צ-08 RTL: כל מסך מיושר לימין; כרטיס "שלח לכל הפנויים" (בדיקת ת-12).

- צ-10 מצבי-ריק/טעינה/שגיאה בכל רשימה → אמת: ברורים ומועילים.

## הרצה עם שני משתמשים (חובה לאזורים ג'–ה')
הפעל שני אמולטורים, התחבר בשני משתמשי-בדיקה נפרדים. לכל פעולה הדדית בדוק את **שני** הצדדים: הרשמה/ביטול → הצד השני רואה עדכון; קידום מהמתנה → פוש+מצב; משחק חי → סנכרון טיימר/תוצאה; סטטיסטיקות → עדכון אצל שניהם. אל תסתמך על שינוי במסד — אמת מה שהמשתמש רואה בפועל, כולל אחרי פתיחה-מחדש.
